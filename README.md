# 🚛 Генератор коммерческих предложений

Автоматический генератор КП для автовозов: лоты машин для перевозки + ИИ (GigaChat) и шаблоны.

## ✨ Возможности

- 📍 **3 региона:** Юга, Владивосток, Восток
- 🤖 **Два режима работы:**
  - Классический генератор на шаблонах
  - Версия с облачным ИИ (**GigaChat** — быстро, нужен API-ключ)
- 💰 **Выбор типа оплаты:** безнал с НДС / безнал без НДС / наличные / обсуждается
- 📋 Копирование в буфер обмена
- 📄 Экспорт в Word (1 или 3 варианта)
- 💾 Автосохранение выбора городов, региона и типа оплаты
- 🎨 Креативный режим «Без города» для Востока
- ⚡ Асинхронная генерация — интерфейс не «зависает»
- 📊 Логирование всех действий (без секретов)
- 📦 **Автономный EXE** — работает без установки Python
- 🔑 **Ввод ключа GigaChat прямо в окне** (кнопка `🔑 Ключ`)
- 📋 **Кнопка «Диагностика»** — показывает `.env`, ключ (маскирован), модель,
  scope, сертификат Минцифры, путь к логам, зависимости и итоговый вердикт
- ⚠️ **Проверка сертификата при старте** — предупреждение в окне ещё до первого
  запроса к GigaChat, а не по факту ошибки
- 🔄 **Fallback на шаблоны** — при любой ошибке ИИ программа продолжает работать

## 🚀 Быстрый старт

### Вариант А. Готовый EXE (Python не нужен)

1. Скачайте/соберите папку `Генератор_КП_GigaChat\` (см. [Сборка EXE](#-сборка-exe)).
2. Запустите `Генератор_КП_GigaChat.exe` **внутри этой папки** двойным кликом.
3. Нажмите `🔑 Ключ` и вставьте Authorization Key — он сохранится в `.env`
   **в той же папке, где лежит `.exe`**.

> ⚠️ Копировать и переносить нужно **всю папку целиком**. Один `.exe` без
> подпапки `_internal\` не запустится.

### Вариант Б. Запуск из исходников

**Установка (Windows) — по шагам:**

1. Скачайте **Python 3.10+** с [python.org](https://www.python.org/downloads/)
   и при установке отметьте галочку **«Add python.exe to PATH»**.
2. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

3. Скачайте **корневой сертификат Минцифры** (нужен для GigaChat):
   https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer

   Положите файл в папку проекта — подойдёт любое из двух мест:

   ```
   config\russian_trusted_root_ca.cer
   russian_trusted_root_ca.cer
   ```

   При сборке он попадёт в папку сборки автоматически. Подробности —
   в разделе [Ошибка SSL](#-ошибка-ssl-certificate-verify-failed).
4. Запустите `scripts\Генератор КП.bat` (двойной клик).
5. Введите ключ GigaChat — пункт **[4]** меню.
6. Запустите программу — пункт **[2]** меню.

Проверить, всё ли на месте, можно кнопкой **📋 Диагностика** прямо в окне
программы: она показывает `.env`, ключ (маскирован), сертификат Минцифры,
путь к логам и итоговый вердикт.

Если сертификата нет, но ключ задан, программа покажет в окне немодальную
плашку **«⚠️ SSL-сертификат Минцифры не найден…»** — это предупреждение,
работать она не мешает.

| Что запустить | Команда |
|---|---|
| Без ИИ (шаблоны) | `python src/генератор_кп.py` |
| С GigaChat (нужен ключ) | `python src/генератор_кп_gigachat.py` |

### Меню запуска (Windows)

Дважды кликните `scripts/Генератор КП.bat` — откроется меню:

| Пункт | Действие |
|---|---|
| **[1]** | Запустить генератор (шаблоны, без ИИ) |
| **[2]** | Запустить генератор (GigaChat — облачный ИИ) |
| **[3]** | Установить библиотеки |
| **[4]** | Ввести API-ключ GigaChat |
| **[5]** | Создать ярлык на рабочем столе |
| **[6]** | Очистить логи |
| **[7]** | Выход |

## 📦 Сборка EXE

```bash
python scripts/setup.py
```

или просто двойной клик по `scripts\build.bat`.

Установщик сам:

1. проверит версию Python и поставит зависимости (`python-docx`, `pyperclip`,
   `requests`, `gigachat`, `python-dotenv`, `pyinstaller`);
2. установит **pre-commit hook** — защиту от попадания ключа в Git;
3. соберёт программу **через spec-файлы** в режиме **`--onedir`**
   (не набором ключей в командной строке);
4. **докладывает в папку сборки `.env`, `.env.example` и `config\`** —
   ключ GigaChat и сертификаты оказываются рядом с EXE автоматически,
   вручную копировать ничего не нужно (см. `ensure_data_files()`);
5. скопирует готовые **папки** сборки на рабочий стол;
6. **проверит пробным запуском**, что программа действительно стартует.

> `.env` попадает только в `dist\` и на рабочий стол — это локальные папки,
> обе в `.gitignore`. В Git ключ не уходит: pre-commit hook это блокирует.

### Что получится

Программа собирается в режиме **`--onedir`** — на выходе получается **папка**,
а не один файл:

```
dist\
├── Генератор_КП_GigaChat\
│   ├── Генератор_КП_GigaChat.exe   ← запускать ЭТОТ файл (~13 МБ)
│   ├── _internal\                  ← Python и все библиотеки (~84 МБ)
│   ├── .env                        ← ключ GigaChat (копируется при сборке)
│   ├── .env.example                ← образец настроек
│   └── config\                     ← сертификаты (Минцифры, набор TLS)
└── Генератор_КП_Шаблон\
    ├── Генератор_КП_Шаблон.exe     ← запускать ЭТОТ файл (~4 МБ)
    ├── _internal\                  ← (~34 МБ)
    └── config\
```

**Папка сборки самодостаточна:** её можно скопировать на другую машину
целиком (или упаковать в ZIP) — ключ и сертификат уже внутри.

| Папка | Назначение | Размер |
|---|---|---|
| `dist\Генератор_КП_GigaChat\` | Версия с ИИ. Нужен ключ GigaChat | ~97 МБ |
| `dist\Генератор_КП_Шаблон\` | Шаблонная версия. Работает **без ключа и без интернета** | ~38 МБ |

Запуск:

```bash
dist\Генератор_КП_GigaChat\Генератор_КП_GigaChat.exe
dist\Генератор_КП_Шаблон\Генератор_КП_Шаблон.exe
```

Сам `.exe` — это только загрузчик, все зависимости лежат рядом в `_internal\`.

### ✅ Почему `--onedir`, а не `--onefile`

Раньше программа собиралась в **один файл** (`--onefile`), и это
**не работает** на машинах с Kaspersky или Pro32. Вот почему:

| | `--onefile` (старое) | `--onedir` (текущее) |
|---|---|---|
| Что на выходе | один `.exe` на ~55 МБ | папка: `.exe` + `_internal\` |
| Что при запуске | распаковывает всё в `%TEMP%\_MEIxxxxx\` | ничего не распаковывает |
| Антивирус | ❌ блокирует распаковку в `%TEMP%` | ✅ вмешиваться не в чем |
| Скорость старта | медленнее (распаковка каждый раз) | быстрее (~1 с) |

**Симптом старой сборки:**

```
Error
Could not create temporary directory!
[OK]
```

Окно даже не успевало появиться. Исключения антивируса на папку проекта
здесь **не помогают**: распаковка идёт в `%TEMP%`, а не в папку программы.

**Преимущества `--onedir`:**

- не распаковывается в `%TEMP%` при запуске;
- антивирусы не блокируют — нет подозрительной активности;
- быстрее стартует;
- сборка не «дописывается» в готовый `.exe`, поэтому антивирус не может
  оборвать её на финальном шаге.

Минус один: получается папка, а не один файл. Решается двумя способами:

| Способ | Как |
|---|---|
| **ZIP-архив** (проще всего) | Правый клик по папке → «Отправить» → «Сжатая ZIP-папка» |
| **Установщик Inno Setup** | В программе есть кнопка **«🔨 Сборка»** — она создаёт папку `Setup\` с файлом `setup.iss` и инструкцией |

### 📤 Как перенести на другой компьютер

1. Скопируйте **ВСЮ папку** `dist\Генератор_КП_GigaChat\` (или
   `dist\Генератор_КП_Шаблон\`) — целиком, со всем содержимым.
2. **Не копируйте `.exe` отдельно** — он не заработает без `_internal\`.
3. Удобнее всего упаковать папку в ZIP: правый клик → «Отправить» →
   «Сжатая ZIP-папка».
4. Python на целевой машине **не нужен** — всё внутри папки.

Для удобства запуска сделайте ярлык: правый клик по `.exe` внутри папки →
«Отправить» → «Рабочий стол (создать ярлык)».

### ⚠️ Про антивирус (для `--onedir` уже не актуально)

> **Для текущей сборки `--onedir` этот раздел не нужен.** Причина простая:
> `--onefile` дописывал десятки мегабайт в уже созданный `.exe` на финальном
> шаге, и антивирус обрывал эту операцию. В `--onedir` `.exe` — маленький
> загрузчик, а библиотеки просто раскладываются по файлам в `_internal\`,
> поэтому обрывать нечего.

Раздел оставлен на случай, если вы соберёте `--onefile` вручную или
вернётесь к старой схеме.

Антивирус (Kaspersky, Pro32, Defender) проверяет файл, который PyInstaller
дописывает на финальном шаге, и **обрывает сборку**. Симптом:

```
PermissionError: [WinError 5] Access is denied: '...Генератор_КП_GigaChat.exe'
Error: _append_data_to_exe
```

В результате в `dist\` остаётся **заглушка ~0,33 МБ (345 600 байт) вместо ~57 МБ**.
Такой EXE не запускается — это огрызок без кода и библиотек.

**Решение (только если вы всё-таки собираете `--onefile`):**

1. Добавьте папку проекта в исключения антивируса:

   | Антивирус | Где добавить |
   |---|---|
   | **Kaspersky** | Настройки → Угрозы и исключения → Исключения → Добавить → `E:\Prpgrammy\Шаблоны` |
   | **Pro32** | Настройки → Защита → Исключения → Добавить папку |
   | **Defender** | Параметры → Обновление и безопасность → Защита от вирусов → Исключения |

2. Запустите сборку заново: `scripts\build.bat` (или `python scripts/setup.py`).
3. Готовый файл появится на рабочем столе.

> Полезно также исключить папки `build\` и `dist\` — PyInstaller пишет туда
> десятки мегабайт, и антивирус тормозит сборку, проверяя каждый файл.
> Для `--onedir` это лишь ускоряет сборку, но ничего не ломает.

Ключи установщика:

```bash
python scripts/setup.py --build-only     # только сборка, без установки зависимостей
python scripts/setup.py --skip-template  # не собирать шаблонную версию
python scripts/setup.py --no-desktop     # не копировать папки на рабочий стол
python scripts/setup.py --no-test        # без пробного запуска
python scripts/setup.py --desktop-dir D:\KP   # положить копию в другую папку
```

### Где программа хранит свои данные

Сборка автономна: **Python на целевой машине не нужен**, все библиотеки лежат
в подпапке `_internal\`. Пользовательские данные лежат рядом с `.exe` — то есть
**внутри папки сборки**:

```
dist\Генератор_КП_GigaChat\        ← вся эта папка и есть «программа»
├── Генератор_КП_GigaChat.exe      ← запускается он
├── _internal\                     ← Python и библиотеки (не трогать!)
├── .env                           ← ключ GigaChat (копируется при сборке)
├── .env.example                   ← образец настроек
├── settings.json                  ← выбранные города и регион
├── logs\                          ← логи работы (появляется при первом запуске)
└── config\
    ├── russian_trusted_root_ca.cer  ← сертификат Минцифры (см. ниже)
    └── ca_bundle_merged.pem         ← общий набор корней (создаёт программа)
```

> 💡 **Можно просто положить `.env` рядом с `.exe`** — программа найдёт его
> автоматически. Файл `.env` ищется в трёх местах по порядку: рядом с `.exe`,
> в текущей рабочей папке, затем в корне проекта.
>
> Проверить, какой именно файл найден, можно кнопкой **📋 Диагностика**.

> 💡 **Сертификат Минцифры можно положить и просто рядом с `.exe`** (не в
> `config\`) — программа проверяет оба места и ещё несколько запасных.
> Полный список видно в **📋 Диагностика**.
>
> Если `config\` недоступна для записи (например, программа лежит в
> `Program Files`), общий набор сертификатов собирается во временной папке —
> проверка TLS работает в любом случае.

> ⚠️ **Папку `_internal\` удалять и переименовывать нельзя** — без неё `.exe`
> не запустится. Это не «лишние файлы», а сам Python с библиотеками.

### Логи

| Способ запуска | Куда пишутся логи |
|---|---|
| Сборка (`--onedir`) | `logs\` рядом с `.exe` — то есть `dist\Генератор_КП_GigaChat\logs\` |

## 🤖 GigaChat (опционально, облачный ИИ)

### Получение ключа

1. Регистрация: https://developers.sber.ru/
2. Личный кабинет → Настройки → Authorization Key (base64)

### Ввод ключа

**Из интерфейса (проще всего):** запустите программу и нажмите `🔑 Ключ`.

**Из меню:** `scripts\Генератор КП.bat` → пункт **[4]**.

**Вручную:** создайте `.env` (рядом с `.exe` или в корне проекта):

```
GIGACHAT_CREDENTIALS=ваш_ключ_из_личного_кабинета
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_TIMEOUT=60
GIGACHAT_VERIFY_SSL_CERTS=true
GIGACHAT_CA_BUNDLE_FILE=
GIGACHAT_BASE_URL=https://gigachat.devices.sberbank.ru/api/v1
```

Если ключа нет, программа **не падает**: она работает на шаблонах и показывает
в окне подсказку «⚠️ Ключ GigaChat не задан. Нажмите 🔑 для ввода».

### ⚙️ Переменные `.env`

| Переменная | Описание | По умолчанию |
|---|---|---|
| `GIGACHAT_CREDENTIALS` | Authorization Key (base64) | — |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` / `_B2B` / `_CORP` | `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | Модель | `GigaChat` |
| `GIGACHAT_TIMEOUT` | Таймаут запроса, сек | `60` |
| `GIGACHAT_VERIFY_SSL_CERTS` | Проверка SSL-сертификата | `true` |
| `GIGACHAT_CA_BUNDLE_FILE` | Путь к корневому сертификату Минцифры | — |
| `GIGACHAT_BASE_URL` | Адрес API GigaChat | `https://gigachat.devices.sberbank.ru/api/v1` |

> **Почему `GIGACHAT_BASE_URL` задан явно.**
> С версии библиотеки `gigachat` 0.2.0 значением по умолчанию стал адрес
> `https://api.giga.chat/v1`, а он доступен не из всех сетей: TCP-соединение
> к нему не устанавливается, и запрос падает с `ConnectTimeout [WinError 10060]`
> через ~21 секунду. Авторизация при этом проходит, потому что идёт на другой
> хост, — из-за этого ошибка выглядит «странной»: прогрев работает, а генерация нет.
> Классический адрес Сбера работает стабильно, поэтому он указан явно.
> Пустая строка = взять адрес по умолчанию из кода (тоже адрес Сбера).

### ⚠️ Безопасность

- Ключ хранится только в `.env`, который указан в `.gitignore`
- Никогда не коммитьте `.env` в Git; в репозитории есть **pre-commit hook**,
  который блокирует такой коммит автоматически
- При утечке ключа — отзовите его в личном кабинете GigaChat
- Ключ маскируется в логах как `***` и не попадает ни в логи, ни в `settings.json`

## 🔒 Ошибка SSL (`certificate verify failed`)

### Как это выглядит

```
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed:
self-signed certificate in certificate chain
```

В окне появляется красная плашка **«⚠️ SSL: …»** с кнопкой **«Как исправить»**.
Плашка **немодальная** — она ничего не блокирует.

Плашка показывается в двух случаях:

1. **сразу при старте** — если сертификата Минцифры нет, а ключ задан
   (раньше о проблеме можно было узнать только по факту ошибки);
2. после запроса, упавшего по сертификату.

В обоих случаях программа **не падает**: текст КП собирается по шаблонам,
копирование и экспорт в Word работают как обычно (см. [Fallback](#fallback-при-ошибке-ии)).

### Почему так происходит

1. **сертификата Минцифры нет там, где его ищет программа** — GigaChat отвечает
   по HTTPS, и без корневого сертификата Минцифры его цепочка не проверяется;
2. либо антивирус (Kaspersky, Pro32, Dr.Web и подобные) или корпоративный
   прокси **подменяет TLS-сертификат своим** (SSL-инспекция) — тогда в цепочке
   появляется «self-signed certificate» и подписывает её **корень антивируса**.

При этом важно понимать: Python проверяет TLS **по своему файлу корневых
сертификатов** (certifi). Он **не читает хранилище сертификатов Windows** —
поэтому сертификат, установленный в системе, программе сам по себе не помогает.

### Решение (по шагам)

1. Скачайте сертификат:
   https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer
2. Положите его в папку `config` рядом с программой — **или просто рядом
   с программой**, программа проверяет оба места:

   ```
   config\russian_trusted_root_ca.cer
   russian_trusted_root_ca.cer
   ```

   Полный список мест поиска (в порядке приоритета) — в отчёте
   **📋 Диагностика**, раздел «🔎 Где искали сертификат», и в логе.
3. **Готово — путь прописывать не нужно.** При запуске программа собирает
   один общий файл корневых сертификатов и сама подставляет его в
   `GIGACHAT_CA_BUNDLE_FILE`.

Если сертификат лежит в другом месте, укажите путь явно в `.env`:

```
GIGACHAT_CA_BUNDLE_FILE=C:\certs\russian_trusted_root_ca.cer
```

> При явно заданном `GIGACHAT_CA_BUNDLE_FILE` ваш путь используется как
> основной, но программа всё равно добавляет к нему штатные корни — иначе
> перестали бы проверяться обычные сайты.

### Что такое «общий набор сертификатов»

Проверка TLS в Python принимает **один файл**. Как только программа
подставляет сертификат Минцифры, набор корней от certifi перестаёт
использоваться — и в сети с SSL-инспекцией проверка падает, потому что
подменённую цепочку подписывает корень антивируса.

Поэтому при запуске программа собирает **один файл из всех нужных корней**:

| Что попадает в набор | Зачем |
|---|---|
| Сертификат Минцифры | без него GigaChat не проверяется вообще |
| Все `*.cer` / `*.crt` / `*.pem` из `config\` | свои и корпоративные корни |
| Корень антивируса из хранилища Windows | именно он подписывает подменённую цепочку |
| Штатный `cacert.pem` от certifi | чтобы не потерять обычные корни |

Файл называется `ca_bundle_merged.pem`, лежит рядом с программой (в `config\`)
и пересобирается только при изменении исходных сертификатов. Дубликаты
отсекаются по отпечатку. **Править его вручную не нужно.**

### Если сертификат уже лежит, но ошибка осталась

Значит, цепочку подменяет антивирус или прокси. Порядок действий:

1. Откройте **📋 Диагностика** — в разделе SSL будет видно, найден ли файл
   сертификата, по каким путям программа его искала и **обнаружена ли
   SSL-инспекция** (с названием корня антивируса).
2. Корень антивируса программа добавляет в набор автоматически, поэтому
   чаще всего достаточно **перезапустить программу**.
3. Если не помогло — добавьте программу (или папку проекта) **в исключения
   SSL-инспекции**:

   | Антивирус | Где отключить проверку |
   |---|---|
   | **Kaspersky** | Настройки → Настройки сети → «Проверять защищённые соединения» → исключить приложение |
   | **Pro32** | Настройки → Защита → Исключения / SSL-инспекция |
   | **Defender** | Практически не подменяет TLS; проверьте корпоративный прокси |

3. Перезапустите программу.

В логе при SSL-ошибке теперь пишется **полный контекст**: причина, все пути
поиска сертификата, найденные корни SSL-инспекции, ссылка на скачивание и
traceback — разбирать проблему можно по логу, без повторного воспроизведения.

### Кнопка «🔑 Ключ» не сохраняла ключ

Раньше при вводе ключа кнопкой **«🔑 Ключ»** могло выскочить «Ключ не введён»,
а `.env` не обновлялся. Что изменилось:

- **ключ сохраняется в тот `.env`, который программа реально читает** —
  рядом с `.exe` для сборки, в корне проекта при запуске из исходников
  (`save_gigachat_key()` и `get_env_write_path()` больше не расходятся);
- **введённое значение очищается** (`sanitize_key()`): убираются пробелы,
  кавычки, перевод строки, BOM, неразрывный и нулевой пробелы, которые
  попадают в ключ при копировании из браузера. Внешне верный ключ с таким
  «хвостом» сервер отвергал как неверный;
- **в диалоге видно длину ключа** — сразу понятно, вставился он или поле пустое;
- **Ctrl+V чистит ключ при вставке** и не даёт Tkinter вставить мусор;
- **плашка «Ключ не задан» исчезает сразу** после сохранения — раньше она
  оставалась до перезапуска и выглядела как «ключ не сохранился»;
- **кэш клиента сбрасывается** (`reset_gigachat_client()`), поэтому новый
  ключ действует без перезапуска программы.

### Чего делать не нужно

❌ **Не отключайте проверку** (`GIGACHAT_VERIFY_SSL_CERTS=false`).
Это убирает защиту от подмены трафика, а проблему не решает. Допустимо только
для локальной отладки.

Программа **не скачивает сертификат сама** — это сделано осознанно:
автоматическая загрузка корневого сертификата из сети — это ровно та атака,
от которой сертификат и защищает.

## 🔄 Fallback при ошибке ИИ

Если GigaChat не ответил — программа **не падает и не зависает**, а собирает
текст по шаблонам. Причины, при которых включается fallback:

| Причина | Что видно в окне / логе |
|---|---|
| Ключ не задан | «⚠️ Ключ GigaChat не задан» + кнопка `🔑 Ключ` |
| Нет сертификата Минцифры | Плашка «⚠️ SSL-сертификат Минцифры не найден…» |
| Ошибка SSL | Плашка «⚠️ SSL: не удалось проверить сертификат» |
| Нет сети / сервер недоступен | Запись в логе, текст — шаблонный |
| `ConnectTimeout [WinError 10060]` | Проверьте `GIGACHAT_BASE_URL` в `.env` (см. выше): адрес по умолчанию `api.giga.chat` доступен не из всех сетей |
| Таймаут запроса | Запрос прерывается по `GIGACHAT_TIMEOUT` (по умолчанию 60 сек), затем один автоматический повтор |
| Пустой или некачественный ответ | Ответ не проходит валидацию — берётся шаблон |

В логе это выглядит так:

```
GigaChat не вернул текст (1.41 сек) — будет fallback
🔄 Использован шаблонный текст (fallback)
```

Что важно:

- **таймаут есть всегда** — «зависнуть» на недоступной сети программа не может;
- **ключ не попадает в текст ошибки** — он маскируется как `***`;
- отключить ИИ вручную можно кнопкой **❌ ИИ / ✅ ИИ** на главном окне.

## 🛠️ Если программа не запускается

Начиная с текущей версии любая ошибка попадает в лог с полным трейсбеком,
поэтому «молчаливого» закрытия окна больше быть не должно.

**Порядок действий:**

1. Откройте `logs\generator_ГГГГММДД.log` (рядом с `.exe` или в корне проекта)
   и посмотрите последние строки — там будет причина.
2. Нажмите в окне **📋 Диагностика**: видно, какой `.env` найден, есть ли ключ,
   подхватился ли сертификат.
3. Проверьте `scripts\pre-commit` установлен ли hook:
   `git config core.hooksPath` (пусто = hook берётся из `.git/hooks/`).

### Частые причины

| Симптом | Причина и решение |
|---|---|
| Окно мигнуло и исчезло | Смотрите лог: там теперь есть трейсбек. Чаще всего — занятая папка `logs` или второй экземпляр программы |
| Программа закрылась сама | В логе будет строка «Главный цикл завершился БЕЗ команды закрытия окна» — значит, программу закрыла другая программа (антивирус, диспетчер задач) |
| `GigaChat: настроен=False` | Ключ не задан или `.env` не найден. Нажмите 📋 Диагностика и 🔑 Ключ |
| `GigaChat: настроен=True`, но текст шаблонный | Скорее всего SSL или сеть. Откройте 📋 Диагностика → раздел SSL, затем лог |
| `[SSL: CERTIFICATE_VERIFY_FAILED]` | Нет сертификата Минцифры (ни в `config\`, ни рядом с программой) или антивирус подменяет сертификат — см. [Ошибка SSL](#-ошибка-ssl-certificate-verify-failed) |
| `.exe` в `dist\` собран размером ~0,33 МБ | Такое бывает только у `--onefile`: сборку оборвал антивирус — см. [Сборка EXE](#-сборка-exe) |
| `PermissionError: [WinError 5]` при сборке | Антивирус держит файлы в `dist\`. Добавьте папку в исключения и повторите сборку |
| `Could not create temporary directory!` при запуске | Это запущена **старая onefile-сборка**. Пересоберите в `--onedir` — см. [Почему `--onedir`](#-почему---onedir-а-не---onefile) |
| После переноса на другой ПК: «не найдена python314.dll» / окно не появляется | Скопировали только `.exe` без папки `_internal\`. Копируйте папку целиком |
| В логе `self-signed certificate in certificate chain` | Подмена TLS антивирусом или прокси: исключите программу из SSL-инспекции |
| Word-файл не сохраняется | На машине нет папки «Рабочий стол» — файл уйдёт в «Документы» или рядом с программой, точный путь показан в сообщении |

## 🔐 Защита от утечки ключа

В проекте включена автосинхронизация с GitHub (`scripts/sync-to-github.ps1`),
поэтому перед каждым коммитом работает **pre-commit hook**:

- блокирует `.env`, `.env.local`, `settings.json`, `settings.user.backup.json`;
- блокирует файлы `*.key`, `*.pem`, `*.pfx`, `*.p12`, `*.log`;
- блокирует любой файл, внутри которого найден непустой
  `GIGACHAT_CREDENTIALS`;
- предупреждает о строках, похожих на другие секреты.

Установить hook вручную (например, после клонирования репозитория):

```bash
python scripts/setup.py          # установщик ставит hook автоматически
```

или вручную:

```bash
copy scripts\pre-commit .git\hooks\pre-commit
```

> Hook лежит в `.git/hooks/`, а папка `.git` в репозиторий не попадает —
> поэтому после клонирования его нужно установить заново.

Если автосинхронизация попробует закоммитить секрет, коммит будет **отменён**,
а в `logs\sync_*.log` появится запись об ошибке коммита.
